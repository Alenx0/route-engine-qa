# BUG-005: El registro informa que se envió el correo de verificación aunque el envío falló

- **Fecha:** 2026-11-04
- **Módulo:** Registro de empresa (POST /api/auth/register)
- **Severidad:** Baja
- **Prioridad:** Media
- **Entorno:** local, Chrome, Windows
- **Caso relacionado:** CP-LOGIN-016

## Precondiciones
- Backend y frontend corriendo en local.
- Servicio de correo (Resend) configurado.

## Pasos para reproducir
1. Abrir /register.
2. Ingresar nombre de empresa "QA Prueba", email de contacto qa.registro@example.com y una clave válida.
3. Enviar el formulario.

## Resultado esperado
Si el correo de verificación no se puede enviar, el sistema avisa al usuario (o permite reenviarlo) en vez de afirmar que se envió.

## Resultado obtenido
El registro responde 201 y la pantalla muestra "Enviamos verificación a qa.registro@example.com". En la consola del backend aparece: [EMAIL ERROR] No se pudo enviar a qa.registro@example.com: Invalid `to` field. El usuario no recibe ningún correo y no sabe que falló.

## Evidencia
- Pantalla de éxito del registro.
- Línea [EMAIL ERROR] en la consola del backend, seguida de POST /api/auth/register 201.

## Notas
- Causa probable: send_email captura la excepción, solo imprime en consola, y register no revisa el resultado.
- El fallo de esta prueba se provocó con un dominio que Resend rechaza (example.com). No se probó con un correo real.
- Existe el endpoint de reenvío (resend-verification), pero la pantalla de éxito no lo ofrece.
- Corrección sugerida: devolver si el envío falló y mostrar un aviso con opción de reenviar.
