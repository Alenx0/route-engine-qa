# BUG-004: Una clave de más de 72 bytes provoca error 500 en el login

- **Fecha:** 2026-11-03
- **Módulo:** Autenticación (POST /api/auth/login)
- **Severidad:** Media
- **Prioridad:** Media
- **Entorno:** local, Chrome, Windows
- **Caso relacionado:** CP-LOGIN-009

## Precondiciones
- Backend y frontend corriendo en local.
- Existe el usuario admin@alenxo.

## Pasos para reproducir
1. Abrir /login con DevTools > Network abierto y filtro "login".
2. Ingresar admin@alenxo como usuario.
3. Ingresar como clave 1000 caracteres (por ejemplo, la letra "a" repetida).
4. Hacer clic en Entrar.

## Resultado esperado
El sistema rechaza el login con 401 "Credenciales inválidas", igual que con cualquier clave incorrecta.

## Resultado obtenido
Responde 500 (191 ms). La pantalla muestra "Error al iniciar sesión" y permanece en /login.
Traceback del backend: ValueError: password cannot be longer than 72 bytes, truncate manually if necessary. Origen: app/api/auth_routes.py, línea 176, función login, llamada a bcrypt.checkpw.

## Evidencia
- Network: POST /api/auth/login con Status 500.
- Consola del backend: traceback completo con el ValueError.

## Notas
- Causa: la versión de bcrypt instalada rechaza claves de más de 72 bytes con una excepción, y login no la captura.
- Corrección sugerida: validar el largo de la clave antes de llamar a bcrypt y responder 401 (o 400) si supera el límite; capturar ValueError.
- Confirmado: con un usuario inexistente la respuesta es 401 (76 ms), porque el código no llega a bcrypt. Con un usuario real, la misma clave da 500. La diferencia delata qué usuarios existen (se suma a BUG-002).
- Confirmado: el límite exacto es el byte 73. Una clave de 72 caracteres da 401 y una de 73 da 500.
- El límite es en bytes, no en caracteres: los caracteres con tilde o la ñ pesan 2 bytes, así que una clave más corta que 72 caracteres también puede fallar. Sin probar.
- Hipótesis sin verificar: register y reset_password llaman a bcrypt.hashpw sin límite de largo y podrían fallar igual con una clave larga.
