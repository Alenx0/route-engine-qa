# BUG-002: El tiempo de respuesta del login revela si un usuario existe

- **Fecha:** 2026-11-03
- **Módulo:** Autenticación (POST /api/auth/login)
- **Severidad:** Baja
- **Prioridad:** Baja
- **Entorno:** local, Chrome, Windows
- **Caso relacionado:** CP-LOGIN-003

## Precondiciones
- Backend y frontend corriendo en local.
- Existe el usuario admin@alenxo. No existe noexiste@alenxo.

## Pasos para reproducir
1. Abrir /login con DevTools > Network abierto y filtro "login".
2. Intentar entrar con noexiste@alenxo y la clave Prueba123. Anotar el Time.
3. Intentar entrar con admin@alenxo y una clave incorrecta. Anotar el Time.
4. Repetir 3 veces cada uno, alternando.

## Resultado esperado
Ambos intentos responden 401 "Credenciales inválidas" en un tiempo similar, de modo que no se pueda deducir si el usuario existe.

## Resultado obtenido
Ambos responden 401 con el mismo mensaje, pero los tiempos difieren de forma constante:
- Usuario inexistente: 22, 29 y 33 ms (promedio ~28 ms)
- Usuario real con clave incorrecta: 300, 316 y 324 ms (promedio ~313 ms)

## Evidencia
Mediciones de la columna Time en Network. Pendiente: adjuntar captura con las líneas ordenadas.

## Notas
- Causa probable: cuando el usuario no existe, el código no llega a bcrypt.checkpw, que es la parte lenta.
- Atenuante: el login tiene límite de 10 intentos por minuto, lo que dificulta explotarlo.
- Corrección sugerida al desarrollo: ejecutar una verificación bcrypt contra un hash falso también cuando el usuario no existe, para igualar los tiempos.
